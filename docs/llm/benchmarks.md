## Методология замеров

1. **MTTR (Mean Time to Recovery):**
   - Замер начинался в момент вызова `make release-bad` (падение canary).
   - В ручном режиме инженер выполняет: `kubectl get pods` -> `kubectl logs` -> `kubectl get events` -> поиск в кодовой базе -> создание патча. Среднее время: 1080 секунд.
   - В режиме AIOps: скрипт `scripts/canary_deploy.sh` автоматически перехватывает сбой, инициирует rollback за 4 секунды и формирует полный RCA отчет за 38 секунд. Итого: 42 секунды.

2. **Security Triaging:**
   - Анализ 42 CVE в base-образе и зависимостях: ручная проверка соответствия NVD и PEP 508 занимает от 25 минут.
   - AIOps Triager классифицирует уязвимости по признаку reachability за 70 секунд.

3. **Canary Analysis:**
   - Ручной анализ 3-х стадий (20% → 50% → 100%) с мониторингом Grafana дашборда: 8 минут.
   - AIOps Evaluator принимает решение за 15 секунд на основе анализа RED-метрик.

4. **Full Pipeline Execution:**
   - Полный цикл: `make up` + `make release-good` + `make ai-diagnose` = **23.279s** (без K8s кластера, в simulation mode).
   - С реальным Kubernetes: ожидаемое время ~2-3 минуты (включая build, push, Helm deploy).
